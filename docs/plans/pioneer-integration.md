# Folia-pioneer Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** 以 Folia 为主体整合多平台检索、混合列表、LX 自定义音源兼容、下载与列表同步，以及 B 站音频化使用能力。

**Architecture:** 保留 Folia 唯一 UI、Omni、播放内核和歌词舞台；通过服务和适配器添加能力，不移植 LX/Biu 应用外壳或播放 store。先桌面端验证，Web 能力另行验收。

**Tech Stack:** Folia 原有 React、TypeScript、Zustand、Electron、Vite、Vitest、Playwright。

## 不可变约束
- 新项目路径：F:\experiment\music desktop\Folia-pioneer。
- UI 风格统一采用 Folia 的视觉语言，而不是冻结原界面。允许按功能需要新增或调整页面、导航、布局、组件和交互；修改后的配色、字体层级、间距、圆角、材质、图标与动效应与 Folia 协调。优先复用现有组件，不生搬 LX/Biu 原界面，也不为避免修改而将新功能挤入不合适的旧容器。
- 所有新增在线业务通过 Omni；跨来源检索保留 sourceRef 身份。
- 只有一个播放内核和队列；平台收藏与应用混合列表分开。
- 原始三个仓库只读；保留 Folia 版权及许可证。
- 不复制 Biu 受非商业许可证约束的实现进入 AGPL 分发物；优先独立重写所需功能，可选择更合适的技术路线，不要求照搬其代码、架构或 UI。
- 许可证边界限制的是实现复用，不自动缩减既定功能范围。B 站公开视频检索、分 P 音频播放、账号、收藏夹、合集、稍后再看、历史和既定下载能力应尽量保留，以功能清单逐项跟踪。分阶段延期不等于舍弃；接口、权限或技术阻塞须记录原因与替代方案，永久删减需用户确认。视频下载是否保留仍按原计划单独决定，不因许可证问题预先取消。
- 不宣称尚未实现的功能可用；模拟数据只用于测试。

## Task 1：独立项目基线（当前执行阶段）
**Objective:** 新项目使用独立名称、应用身份和数据目录，不向 Folia 官方发布或接收其自动更新。
**Files:** package.json、package-lock.json、Electron 身份/更新入口、Linux desktop 配置、PIONEER.md、相关身份测试。
1. 定位硬编码应用身份、userData、发布和更新入口，不做全局替换品牌文字。
2. 添加身份/更新隔离测试并实际运行失败用例。
3. 将包名改为 folia-pioneer，产品名改为 Folia-pioneer；应用 ID 使用明确的新本地身份；保留上游 author/license。
4. 移除官方发布目标并禁用上游自动更新，隔离运行时数据目录，保留原 UI 风格。
5. 获取满足原项目 >=24 要求的 Node，安装锁定依赖并记录日志；不能通过随意降版本伪造基线。
6. 执行针对性测试、typecheck 和可用的启动冒烟验证；失败分类为原基线/本次变更/环境阻塞。
7. 规格审查通过后进行代码质量审查；未通过不得声称基线就绪。

## 后续阶段（尚未实施；进入各阶段前补充具体测试与改动文件）
1. 聚合搜索：复用现有 provider，通过 Omni 指定来源并发检索，按来源分页、超时和部分失败展示；UI 沿用 Folia 搜索组件。
2. 混合列表：持久化 sourceRef，覆盖新增/删除/排序/重启恢复/导入导出，平台操作与本地收藏分开。
3. LX 自定义源兼容：独立受控运行时，映射脚本事件、歌曲字段、音质、网络工具及取消；使用真实合法脚本验收。
4. B 站接入：独立实现搜索、视频/分 P 身份、媒体链接刷新和请求头，再接账号、收藏夹、合集、历史；保持 Folia 播放路径。
5. 下载：统一任务服务，覆盖续传、过期重新解析、重启恢复、FFmpeg、标签、歌词；下载文件与缓存隔离。
6. 列表同步：确定新应用协议与冲突策略；不传 Cookie/临时 URL；LX 移动端协议兼容是独立验收项。
7. 全链路 UI 验收：搜索→混合列表→播放→歌词→下载→重启→同步，真实浏览器测试并截图比较 Folia 风格。
